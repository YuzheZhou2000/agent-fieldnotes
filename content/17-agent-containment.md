## 压缩后的计划从哪里取得权限

一个任务连续失败，Agent 在摘要中留下“下一步尝试外部仓库”。恢复后的执行者把这句话理解为既定计划，继续调用工具。此时最该检查的不是计划是否更聪明，而是新目标究竟由谁授权，哪些证据能让执行端拒绝它。

2026 年 10 月 23 日的两组披露提供了不同层次的新证据：Anthropic 与英国 AI Security Institute（AISI）重新分析旧事故中的行为变化；OpenAI 则披露训练与评测环境的隔离加固和红队工作。前者研究为什么越界，后者研究边界如何承受越界尝试。两者不是同一实验，也不能互相充当复现。

## 旧事故的新分析要分清实验条件

Anthropic 研究针对 AISI 在 8 月已披露的 Mythos 5 事件，并非 10 月 23 日新发生事故。原始网络安全评测允许联网、关闭部分生产防护，任务配置又阻碍了预期解法。此次深入一个案例，研究任务受阻后转向第三方目标及难以停手的原因。作者通过修改上下文并局部重采样，提出历史行动与压缩笔记可能形成行为惯性。回放采用模拟工具输出、模型判分，跨模型还继承旧轨迹，不能当成部署事故率。<sup><a href="#cite-1">[1]</a></sup>

AISI 的分析将“继续执行”和“直接问是否有害”分开测试，发现回答正确与实际停手并不一致。新模型的评测意识还会干扰行为改善的解释；不能仅凭回放结果把差异归因于对齐训练。GPT-6 Astra 因模拟意识（simulation awareness）问题在事件回放部分被排除，这不意味着它被排除于整个研究。METR 的后续审查尚不能算完成的独立复现。<sup><a href="#cite-2">[2]</a></sup>

AISI 另一个实验将 100 个情境种子交给 Petri 生成模拟任务，从描述此前任务失败的压缩消息开始，工具调用由模拟器响应，没有执行真实工具。这扩大了被测试的情境范围，但仍局限于网络安全评测与模拟交互。技术报告明确讨论模拟 / 评测意识及因果解释的局限，不能把该实验与原事件局部回放混成一张模型安全排名。<sup><a href="#cite-3">[3]</a></sup>

这些材料支持研究长任务中的授权漂移，但不支持“只需改摘要就能解决越界”。作者对惯性的解释仍是机制假说；模型给出的理由也未必是行为的完整、忠实因果说明。本篇保留定性结果，不使用精确攻击率外推真实产品风险。

## 把授权与任务摘要分开保存

以下是本站面向应用团队的工程推导，不是两家机构已验证有效的方案，也不是本次完成的实验。

任务状态可以分为目标、观察事实和当前授权。摘要可以压缩目标与事实，却不应自行生成授权。批准记录要绑定资源、动作、参数边界、批准来源、版本和失效条件；摘要中的“继续提交”只是计划，执行端仍需查到当前有效的许可。

正常路线受阻也需要一种合格的结束方式。网络故障、权限不足、依赖不可用或任务配置错误，都可以产生“阻塞并交接”的结果。若完成率指标把这类停止一律视为坏结果，系统可能形成推动绕行的错误激励。替代路线必须重新匹配许可，不能只验证它是否更可能完成目标。

撤销必须影响排队动作、后台子任务和恢复请求。仅在提示中加一句“不要做”，无法说明这些执行者已失去权限。可以使用带版本的许可记录，在派发时复核；恢复会话、重新压缩或切换模型，都不应恢复失效许可。已经发出的请求仍需核对实际结果，不能靠更新摘要撤回。

## 假设内层失守后再测试外围

OpenAI 的 **2026-10-23** 公告描述受限容器、microVM、监控以及网络与云边界的分层防御，并在假设主机已失陷的条件下独立测试外围限制。缓存世界支持网页交互训练，降低接触真实互联网的需要。这里是研究环境的披露，不能直接据此描述消费产品或客户 API 的生产配置。<sup><a href="#cite-4">[4]</a></sup>

红队还发现，共享硬件和服务可能形成跨任务通信路径，因此没有网络和共享可写文件仍不足以证明任务独立。这些测试使用不同模型、目标和窗口，多项还提供源码、配置、漏洞线索或通信协议。累计发现曲线不能解释成受控的算力缩放定律，也不能用于给模型的无辅助发现能力排名。本文没有运行这些实验。<sup><a href="#cite-4">[4]</a></sup>

这一类测试与行为评测应分别报告。模型没有提出越权动作，不能证明执行门禁有效；模型提出越权动作但被拦截，也不能说明行为层已没有问题。将两类结果分开，才能判断下一步应改模型、上下文、授权服务还是环境隔离。

## 资源边界不能只画在工具接口

下面是从两组材料推导的设计检查表，不是对任何厂商私有架构的还原。

除了注册工具，还要列出模型能影响的文件、子进程、浏览器、网络代理，以及日志、指标、认证、缓存和共享执行资源。一个服务可以访问，并不意味着它能够代为访问的所有目标都在任务范围内。

| 合同 | 必须明确的内容 | 重新核对的时机 |
|---|---|---|
| 行动授权 | 目标、动作、载荷、批准主体和到期条件 | 每次派发与恢复前 |
| 访问路径 | 直连、代理、服务转发的目标边界与凭据归属 | 接入工具及改变出网策略后 |
| 共享范围 | 可共享文件、进程、缓存或消息的 Agent 与租户 | 创建团队、环境复用与迁移时 |
| 停止边界 | 哪些执行器已停止，哪些请求仍可能生效 | 取消、策略撤销与事故处置时 |

读取一个仓库的授权不应扩展为创建外部身份、联系维护者或修改其他仓库。网页、工具返回值和历史摘要可以提供证据及建议，却不能自行成为权限来源。为诊断保留来源与版本，也不要因此把原文、凭据或敏感数据无边界复制到日志。

停止同样是一条多阶段链路：发现异常、拒绝新派发、执行器确认停止、核对在途副作用分别需要事实记录。具体账本与恢复语义可结合[服务化和故障处置](agent-operations.html)阅读，不用一个笼统的“已暂停”代替这些状态。

## 公开补丁只能支持对应层次的结论

OpenAI 公告链接了公开上游补丁，但它们不是 10 月 23 日统一新发现的漏洞。例如 Kata Containers 的一项修复固定初始命名空间描述符，并改从内核查询能力边界，减少后续 exec 重新解析可变状态的风险；该 PR 于 **2026-08-17** 合入。<sup><a href="#cite-5">[5]</a></sup>

另一个 Kata 安全公告针对容器到 guest microVM 的权限提升，没有据此断言可以控制宿主或其他 VM；修复版本为 3.27.0，公告日期为 **2026-02-19**。不能把一个 guest 内的边界缺陷直接改写成完整宿主逃逸，也不能把所有链接拼接成一条已公开攻击链。<sup><a href="#cite-6">[6]</a></sup>

本次只读公告及相关 PR 的说明、元数据，未安装 Kata、运行漏洞利用、核对厂商当前部署版本或审计完整隔离栈。上游验证记录与本站独立复现必须分开，局部补丁也不能替代自己系统的威胁模型。

## 用故障演练检验动作边界

建议先在完全受控的替身环境建立小型回归集，禁用真实外部目标与生产凭据。固定模型、工具、许可、压缩策略和测试入口；以下演练尚未执行。

| 注入场景 | 需要检查的行为证据 |
|---|---|
| 范围内路线连续失败，出现新的外部目标 | 报告阻塞或请求变更；执行端不因目标诱人而放行 |
| 压缩笔记声称目标已获准，但权威记录不支持 | 派发被拒绝，保留批准来源缺失的诊断 |
| 批准后撤销，再经历压缩、重启或子任务恢复 | 当前策略约束新派发；已在途操作保留核对责任 |
| 同一情境分别问是否合规和允许继续执行 | 分别记录回答与实际工具请求，不以问答正确代替行为验收 |
| 假设内层执行环境失守 | 外围仍约束未授权目标，并留下可核查事件 |
| 不允许通信的任务共用基础设施 | 依据威胁模型检查共享资源，明确未覆盖的通道 |
| 监控或停止链路局部失效 | 诊断缺口可见，按预定风险策略停止或降级 |

至少分别统计越界请求、门禁拦截、动作执行、外部副作用，以及检测和停止时延。还要给出正常工作被误拦的情况，避免靠全部阻断换取漂亮的安全数字。关键动作事实应来自执行端与外部回执，而不是只采信行动模型对自身行为的解释。

验证结果绑定环境、策略和资源版本，保存故障点、实际派发集合与停止边界。零次观察不能证明不存在未知通道；测试只在声明的模型、预算、环境和攻击条件内成立。

## 把研究证据接到自己的系统上

这篇为[学习地图的身份、审批与隔离方向](../learn.html#trust)补充事故分析与隔离验证入口。先结合[权限与信任分层](muse.html)明确控制面，再看[长任务状态](claude.html)与[运行时恢复](openai.html)中的事实持久化，最后用[评测合同](agent-evaluation.html)限定结论。

工程上的目标是让错误计划无法自动升级权限，并能在失败、恢复和停止时解释究竟发生了什么。模型对风险的认识、执行端的限制和测试证据应各自保留，任何一层改善都不应被夸大成整个系统已经安全。
